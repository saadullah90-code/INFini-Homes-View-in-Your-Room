We are changing the storefront integration strategy for the INFini Homes "View in Your Room" project.

IMPORTANT:
Do NOT delete or rewrite the existing backend architecture.
Do NOT remove the existing admin dashboard, database schema, product/model/job state machine, mock generation, approval/publish workflow, logs, or existing AR token route.
Do NOT change Shopify App Distribution, OAuth, API credentials, Shopify scopes, webhooks, or existing Shopify configuration.
Do NOT start any real Meshy generation.
Do NOT spend any Meshy credits.
Do NOT modify any existing Shopify product images.
Do NOT bulk generate models.

NEW STOREFRONT STRATEGY:
Instead of requiring the Shopify app to be installed for the storefront frontend, we will use a Shopify Custom Liquid section/block on the INFini Homes product page.

The Custom Liquid frontend will communicate with our Replit backend through safe public storefront API endpoints.

The final architecture should be:

SHOPIFY PRODUCT PAGE
    ↓
CUSTOM LIQUID FRONTEND
    ↓
REPLIT PUBLIC STOREFRONT API
    ↓
DATABASE / APPROVED 3D MODEL
    ↓
GLB + USDZ
    ↓
MODEL-VIEWER / AR

The Replit backend will later be moved to Railway without changing the frontend architecture.

PHASE 2 — STOREFRONT API
==================================================

After inspection, create a dedicated public storefront API.

The API must ONLY expose safe published information.

Create an endpoint similar to:

GET /api/storefront/model

Accepted parameters:
- shop
- product_handle
- optionally product_id

Example:

/api/storefront/model?shop=infinihomes.shop&product_handle=example-product

The endpoint must:

1. Validate the shop against an allowlist:
   - infinihomes.shop
   - www.infinihomes.shop

2. Never expose:
   - Shopify Admin API access tokens
   - Shopify API secret
   - Meshy API key
   - database credentials
   - internal admin information
   - generation job internals
   - private file paths

3. Find the matching local product/model.

4. Only return a model when:
   - product is eligible
   - model status is PUBLISHED
   - model has valid GLB
   - required AR asset exists

5. If no published model exists, return a clean response such as:

{
  "available": false
}

6. If published, return only safe fields such as:

{
  "available": true,
  "productHandle": "...",
  "modelUrl": "...",
  "usdzUrl": "...",
  "arUrl": "...",
  "title": "...",
  "version": "...",
  "updatedAt": "..."
}

Do not expose database IDs unless genuinely required.

7. Add CORS support ONLY for:
   https://infinihomes.shop
   https://www.infinihomes.shop

Do not use wildcard "*" CORS for authenticated/admin endpoints.

8. Add reasonable rate limiting to public storefront endpoints.

9. Add strict input validation.

10. Do not allow arbitrary URL fetching through query parameters.
